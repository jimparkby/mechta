# Модуль «Мечта» для кассовой программы: интеграция

Для разработчика кассы (начинаем с MTKassa). Терминал и эквайринг не меняются; вся доработка — три вызова в кассовой программе.

Эталонная реализация — `pos-module/mechta-pos.js` (JS, без зависимостей, ~380 строк), типы — `mechta-pos.d.ts`. Если касса написана не на JS, переносится только логика ниже: HTTP-протокол — это и есть контракт.

## Куда встраивать

```
кассир нажал «Оплата картой»
        │
        ▼
 session = await pos.beforeCardPayment(lines, amount)   ← шаг 1, ДО суммы на терминал
        │                                                    ждёт не дольше 1,5 с, никогда не бросает ошибок
        ▼
 сумма → терминал → банк → ответ терминала               ← шаги 2–6, без изменений
        │
        ▼
 info = await pos.afterCardResult(session, approved)    ← шаг 7
        │
        ├─ info.mechta === true  → показать info.hint / info.cashierText,
        │                          подсветить строки info.removeLines,
        │                          кнопка «Убрать и повторить оплату»
        └─ иначе                 → обычное поведение кассы
```

Кроме этого:

- при старте кассы: `pos.loadCatalog()` (справочник штрихкодов; потом модуль обновляет его сам раз в 6 часов);
- кассир отменил чек или покупатель ушёл: `pos.cancel()`.

```js
const pos = MechtaPos.createPosModule({
  serverUrl: 'https://api.mechta.example',
  terminalId: 'T-1042',          // TID платёжного терминала этой кассы
  merchantId: 'M-000123',        // MID, необязательно
  groupMap: { ALC: 'alcohol', TOB: 'tobacco' }, // группы товаров в базе магазина
  log: (level, msg, data) => kassaLog(level, msg, data)
});
await pos.loadCatalog();
```

## Строка чека

| Поле | Что это |
|---|---|
| `gtin` | штрихкод EAN-13/8 или GTIN-14 |
| `markCode` | код маркировки DataMatrix как есть со сканера (GTIN берётся из него) |
| `group` | группа товара в базе магазина → категория через `groupMap` |
| `category` | категория «Мечты», если касса уже знает: `alcohol`, `tobacco`, `energy`, `lottery` |
| `price`, `qty` | цена за единицу в копейках, количество |
| `sum` | итог строки **после скидок**, в копейках. Если касса его знает — передавать обязательно |

Категория ищется по порядку: `category` → `group` через `groupMap` → справочник сервера по GTIN.

**Сумма.** Сервер сопоставляет чек с оплатой по точному совпадению суммы. Поэтому в `beforeCardPayment(lines, amount)` вторым аргументом передаётся ровно та сумма, которая уйдёт на терминал: после скидок, бонусов, округлений, а при смешанной оплате — только карточная часть.

## Протокол (все суммы в копейках)

| Когда | Запрос | Ответ |
|---|---|---|
| старт | `GET /api/catalog` | `{ version, items: { "<gtin>": { category, name? } } }` |
| шаг 1, только если есть ограничиваемые товары | `POST /api/baskets` `{ terminalId, merchantId?, amount, restricted: { alcohol: 873 } }` | `201 { basketId, expiresInSec }` |
| шаг 7, только после отказа терминала | `GET /api/baskets/:id` | `{ status: pending\|declined\|paid\|closed\|unknown, categories, hint? }` |
| новая оплата, одобрение, отмена | `DELETE /api/baskets/:id` | `{ status: "closed" }` |

Заголовки: `Authorization: Bearer <ключ кассы>` (на пилоте), `X-Mechta-Pos: mechta-pos/<версия>`.
Если чек без ограничиваемых товаров, касса ничего не отправляет. Данных карты и покупателя касса не знает и не передаёт.

## Правила, которые нельзя нарушать

1. **Сбой никогда не мешает оплате.** Таймаут, ошибка сети, 4xx/5xx, кривой ответ — касса молча идёт дальше. Сервер «Мечты» в этом случае не найдёт чек и банк одобрит оплату.
2. **Таймауты:** отправка чека — 1,5 с, закрытие прошлого чека — 0,5 с, выяснение причины отказа — до 2,5 с всего (опрос каждые 250 мс).
3. **Отказ «Мечты» — обычный отказ банка** (код 05). Отменять транзакцию не нужно. Если сервер на шаге 7 отвечает `pending`, значит, банк отказал по своей причине — показать кассиру обычный отказ.
4. **Закрывать старые чеки.** Без этого возможен ложный отказ: после отказа кассир заменил пиво 3,20 на сок 3,20 — сумма та же, сервер нашёл бы старый чек. Модуль закрывает прошлый чек перед каждой новой оплатой, после одобрения и по `cancel()`.
5. Маркированный товар — отдельная строка на каждый код (так касса и так делает для учёта маркировки).

## Сканер

`parseScan(raw)` принимает строку от сканера и возвращает `{ gtin, marked }`. Понимает:

- EAN-13/EAN-8/UPC/GTIN-14;
- GS1 DataMatrix с AI `01` (алкоголь, пиво, табачные блоки), в том числе без символа GS и с префиксом `]d2`;
- код пачки сигарет без AI (25/29 символов, первые 14 — GTIN).

## Что проверено

`npm test` — 19 тестов на Node 18+: пример Ивана из ТЗ (43,75 → отказ → 35,02), обычная карта, незапрещённая категория, отказ банка по другой причине, смешанная оплата, другой терминал, сервер недоступен / завис / отвечает 500, мусор в чеке, выключенный модуль, ложные отказы при той же сумме.
Демо-касса (`pos-demo/`) прогнана в Chromium в двух режимах: с сервером и без него.

## Изменения на сервере, которые понадобились кассе

- Добавлен `DELETE /api/baskets/:id` и статус `closed` (в `server/mechta-core.js`; в `index (5).html` ядро старое).
- Добавлен `GET /api/catalog` в `server/server.js` — в ядре прототипа его не было.

**Для команды сервера:** если повторить ту же оплату после отказа, создаётся новый чек, и сумма запрещённого товара снова идёт в копилку. Сейчас копилка растёт за каждую попытку, а не за каждую остановленную покупку. Касса это не решит; нужно правило на сервере, например не засчитывать повтор того же терминала, категорий и суммы в течение 2 минут.

## Вопросы к MTKassa (из ТЗ, теперь конкретнее)

- Есть ли точка расширения между «Оплата картой» и отправкой суммы на терминал, и можно ли там подождать до 1,5 с?
- Видит ли касса ответ терминала (одобрено / отказ) в коде, чтобы вызвать `afterCardResult`?
- Знает ли касса TID своего терминала? Если на кассе несколько терминалов — какой выбран для этой оплаты?
- Есть ли в базе товаров группа или признак для алкоголя, табака, энергетиков, лотерей → заполнить `groupMap`.
- Знает ли касса итог строки после скидок и точную карточную часть при смешанной оплате?
- На чём написана касса (Android/Kotlin, C#, Java)? От этого зависит, переносить модуль или встраивать JS.
- Нужна ли перерегистрация версии ПО после добавления модуля?
